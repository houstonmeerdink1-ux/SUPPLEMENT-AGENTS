# Pre-Skill Behavior Baseline

**State:** RED behavior evidence captured before `mco-supplement-fast-lane` existed.

Two completed fresh-agent exercises were available from the prior Xactimate work:

1. The no-fast-lane baseline proposed a careful `TEST_PROJECT` preflight, price-list preservation, minimal report, transfer and PDF verification. It did not start from an ordinary customer/job name, lock the exact JobNimbus IDs and address, fingerprint the SONY mirror, run a JobNimbus source delta, or show an unpriced `what is wrong` carrier-scope audit before pricing.
2. The forward Xactimate exercise correctly used the installed pricing helpers and safety gates. It still began after project identity and pricing inputs were already supplied; it did not supply the missing name-to-job, source freshness, cache or scope-approval orchestration.

These are technique/output-shape omissions, not pressure-based rule violations. The new skill therefore needs a positive required sequence with named artifacts and phase gates. Mechanical identity, fingerprint, state and approval constraints belong in tested code rather than prose alone.

The GREEN forward check must demonstrate that a job-name request routes through:

`resolve -> prepare -> live delta -> scope audit -> Houston approval -> Xactimate handoff -> export reconciliation`

Any ambiguous identity, incomplete source, changed source, unresolved scope item, missing price list or unverified export must remain a visible pause state.
